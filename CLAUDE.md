# Технические приёмы

## Большие файлы

**Никогда не читать файл целиком без проверки размера.** Стратегия: `ls -lah` → `head -30` → `grep + head` → якоря.

Запрещено: `cat huge.log`, `Read(file)` без проверки, `grep` без `| head`.

## Shell

- **zsh**: сложные `$()` в циклах — оборачивать в `bash -c '...'`
- **macOS**: нет `timeout` — использовать `run_in_background=true` или `gtimeout`
- **Долгие команды** (>30с): запускать с `run_in_background`. Мониторить через `tail -5`, не через BashOutput без фильтра.

## Временные файлы

Все временные скрипты, логи `run_in_background`, черновики и diff'ы — в **`<cwd>/.tmp/`** (в текущей рабочей директории).

- `mkdir -p .tmp` перед использованием (идемпотентно)
- **Запрещено**: писать в `/tmp/` (на macOS это и `/private/tmp/`), `/var/tmp/`, `~/.claude/tmp/`. В корпоративных средах `/tmp` и `nohup` часто мониторятся
- `.tmp/` уже в глобальном gitignore (`~/.config/git/ignore`) — в коммит не попадёт

Свою временную папку (scratchpad из системного промпта, вывод фоновых задач) Claude Code
держит в каталоге из `CLAUDE_CODE_TMPDIR` (например `~/.tmp/cc/`) — его задаёт `env` в
`~/.claude/settings.json`. Если системный промпт всё же назвал scratchpad в `/tmp` или
`/private/tmp`, настройка слетела: туда не писать, писать в `<cwd>/.tmp/` и сказать пользователю.

# Git

**Для коммитов ВСЕГДА используй `/commit`.** Не коммить напрямую.

Исключение — внутренности коммит-флоу: fix-коммиты цикла `/review` (делает `review-runner`) и `/finalize` (шаг 3c) делаются напрямую через git commit — `/commit` изнутри них не вызывается.

**Подпись коммитов.** Каждый созданный коммит привязывается к сессии: строка `<short-hash> <sessionId> <YYYY-MM-DD> <title>` в `~/.claude/projects/<slug>/memory/commit-sessions.md` (всегда, любой репо). Trailer `Ref: <sessionId>` в message — только если проектный CLAUDE.md явно разрешил (личные репо); дефолт — без следов в репо. Каноника алгоритма — `/commit` секция «Подпись коммита». Вернуться к сессии коммита: grep хэша по журналам → claude --resume <UUID>.

**Дефолт: `git push` требует явного разрешения пользователя.** Если /commit или /review предлагают push, или ветка feature и кажется что push логичен — ВСЁ РАВНО спрашивай. Force-push, обычный push, push в feature-ветку — всё требует явного «да, пушь» от пользователя в текущем сообщении.

**Per-project override.** Конкретный проект может ослабить или ужесточить это правило через свой `CLAUDE.md` или `.claude/CLAUDE.md` — вплоть до авто-push после clean review в одну сторону и запрета даже локального merge в другую. Что именно разрешено — читай в проектном файле, здесь этого знать не нужно. Если override не описан — действует дефолт «спрашивай».

**Пример override.** Личный проект может разрешить авто-push в main после clean review; рабочий репозиторий — наоборот, запретить даже локальный merge без явной просьбы.

# Worktrees

**Любая задача с правкой файлов, которые попадают в ветку, — в worktree, без исключений.** Только чтение/поиск/прямой ответ — напрямую.

**«Без исключений» значит без исключений по размеру.** Одна строка, опечатка, правка правил, правка документации, «на секунду поправить» — тоже worktree. Порога «слишком мелко для ветки» не существует. Правка в основном дереве — ошибка для любого файла, который попадает в ветку, даже если кажется быстрее. Файлы, которые игнорирует git, под это правило не подпадают (см. про хук ниже).

- **Правлю лично** → `EnterWorktree` (в начале), `ExitWorktree` (в конце)
- **Делегирую агенту** → `Agent(isolation: "worktree")`
- **Другой репо, не cwd** (правлю `~/.claude` из проекта) → worktree вручную: `git -C <repo> worktree add <repo>/.claude/worktrees/<name> -b <name>`, коммит через `git -C`; закрытие ветки (merge или pull request) — по CLAUDE.md того репо, который правим
- **Запрет держится хуком** `~/.claude/hooks/worktree-boundary.sh` — `PreToolUse` на Write/Edit/MultiEdit/NotebookEdit откажет в записи в основное дерево любого git-репо, кроме файлов, которые игнорирует git (их нет ни в одной ветке, например `settings.json`); отслеживаемые файлы исключения не получают. Смену ветки основного дерева командами git в Bash (`checkout`, `switch`, `reset --hard`, `branch -f`) держит `~/.claude/hooks/git-branch-guard.py` (`PreToolUse` на Bash)

> Подробнее: `rules/workflow.md` → секция «Изоляция через worktree»

# Tech Debt

**Фиксируй техдолг СРАЗУ через `/techdebt`** — не спрашивай "стоит ли записать?", просто записывай.

**Парное правило: в конце задачи — `/finalize`, обязательно, если в сессии создавался хоть один техдолг.** Записан техдолг — значит разбери, не оставляй висеть. Скилл берёт только техдолги этой сессии, а не весь backlog репо — поэтому запуск дешёвый (детали фильтра и критерий «очевидное/спорное» — `rules/workflow.md` шаг 10 и `skills/finalize/SKILL.md` шаг 2).

Путь хранения определяет сам `/techdebt` (см. `~/.claude/skills/techdebt/SKILL.md` шаг 0 — канонический алгоритм).

При исправлении — удали файл записи и строку из INDEX.md.

# Нити сессии

**Отложенная тема — сразу строка в журнал.** Когда идея или вопрос откладывается («ИДЕЯ», «потом», «обсудим позже», «в очередь»), допиши строку в `~/.claude/projects/<slug>/memory/session-threads.md` (slug по main-репо): `<sessionId> | <YYYY-MM-DD> | <нить одним предложением>` (sessionId — полный UUID текущей сессии, значение `$CLAUDE_CODE_SESSION_ID`). Это формализация правила «не забывать оффтопные идеи»: журнал переживает compaction. Разбор и триаж — `/finalize` шаг 5c.

# Session ID и compaction

Сжатие контекста (compaction) id сессии не меняет (проверено на прошлых сессиях со сжатием: id в транскрипте до и после одинаковый). Id текущей сессии — переменная окружения `$CLAUDE_CODE_SESSION_ID`: Claude Code сам выставляет её в Bash и хуках. У сабагента она равна id главной сессии (это и нужно для привязки коммитов и техдолгов), в форке сессии — свой id.

**Правило:** `sessionId` бери из `$CLAUDE_CODE_SESSION_ID` (`echo "${CLAUDE_CODE_SESSION_ID:-unknown}"`), не из памяти и не из summary, и передавай его в sub-agent (review-judge, /commit, /finalize, /techdebt с parentSessionId). Поведение при пустой переменной — `/commit`, секция «Подпись коммита».

`/techdebt` дополнительно дописывает id в worktree-local `<git root>/.tmp/active-tds.md` — это детерминированный источник для `/finalize`, не зависящий от UUID. Не трогай файл руками.
