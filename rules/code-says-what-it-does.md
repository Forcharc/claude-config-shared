# Код говорит то, что делает

Принцип наименьшего удивления: форма кода — имя, тип и возвращаемый тип, сигнатура, комментарий-контракт, интерфейс и его методы, значение по умолчанию, видимость — говорит ровно то, что код делает в боевом пути. Читатель верит форме и не идёт проверять тело.

## Признаки нарушения

- Член, параметр, метод интерфейса или значение по умолчанию без боевого потребителя: используют только тесты или никто. Параметр по умолчанию, который никто не переопределяет, — тоже сюда.
- Описание обещает порядок, гарантию, ленивость, идемпотентность или потокобезопасность, которых боевой путь не даёт; или ссылается на методы, которые вызывают только тесты.
- Тип или сигнатура не отражают поведение: функция «возвращает ничего», но не завершается сама (`suspend fun prime()` висит до отмены); `bool` или `Unit`, когда исходов несколько.
- Одно имя означает разное в разных местах; два описания одного процесса расходятся. Параметр `retries` в одном месте считает попытки, в другом — повторы после первой. Примеры: Python `def fetch(retries=3)` делает 3 попытки, а конфиг `retries: 3` — 4; TypeScript `timeout` в опциях в секундах, а одноимённое поле ответа в миллисекундах; Java `size` в одном классе число элементов, в другом байты.

## Допустимое

- Шов: интерфейс на границе зависимости с боевой реализацией и фейком в тестовых исходниках. Метод, поле или параметр боевого класса, добавленный ради теста, швом не является; интерфейс только с фейком, без боевой реализации, — тоже не шов. Шов снимает только вопросы о боевом потребителе (нет потребителя, только тесты, неиспользуемый default): имя, сигнатура и описание шва проверяются как у любого кода.
- Точка расширения публичного SDK с задокументированной целью. Снимает только вопросы о боевом потребителе (нет потребителя, только тесты); остальное проверяется как у любого кода.
- Override контракта платформы или фреймворка: форму диктует платформа, не находка вообще.
- Маркер тестового доступа (`@VisibleForTesting`, `@TestOnly` и подобные) смягчает находку, но не отменяет её, если у члена нет боевого потребителя или описание обещает боевую роль.

## Как проверять

По каждому новому члену — Grep потребителей отдельно в боевом коде и в тестах. Каталоги тестов определяй по соглашению проекта: `src/test`, `androidTest`, `test/`, `tests/`, `*Test.*`, `*_test.*`. Совпадения только в тестах — потребителя нет.

## Что делать

Убрать; либо привести форму к делу (описание, тип, имя); либо подключить к боевому пути. «На всякий случай» не оставлять.
