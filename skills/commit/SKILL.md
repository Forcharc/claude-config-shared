# Git Commit

Закоммить текущие изменения. Без подтверждения — сразу делай.

## Шаги:

1. `git log --oneline -5` и `git status` — параллельно. Если нет изменений (ни modified, ни untracked) — сообщи и выйди.

2. Если ничего не застейджено — застейдж все изменённые и новые файлы.
   Не стейджи файлы с секретами (.env, credentials, ключи API).

3. **Атомарность:** если изменения затрагивают несколько несвязанных вещей — разбей на отдельные коммиты. Каждый коммит = одна логическая единица.

4. Определи формат по истории:
   - Тикеты (PROJ-XXXXX, TICKET-XXXXX и т.д.) → `ТИКЕТ: описание` (на русском)
   - Без тикетов → `Краткое описание` (на языке истории коммитов)

5. Сгенерируй commit message:
   - **Вычисли sessionId сейчас** (он нужен и для trailer ниже, и для журнала в шаге 6) — из `$CLAUDE_CODE_SESSION_ID`:
      ```bash
      echo "${CLAUDE_CODE_SESSION_ID:-unknown}"
      ```
   - **Title** (до 50 символов): что сделано. На английском — imperative mood ("Add", не "Added").
   - **Body** (опционально): ПОЧЕМУ сделано, какую проблему решает, контекст. Не пересказывай diff. Для тривиальных изменений body не нужен.
   - **Trailer-подпись (только личные репо, opt-in):** если проектный CLAUDE.md явно разрешает trailer-подпись (формулировка вроде «commit signature trailer: разрешён»), добавь в конец body пустую строку и trailer `Ref: <sessionId>` (sessionId вычислен выше). Без явного разрешения — НЕ добавляй ничего в message (дефолт - без следов в репо, как в CLAUDE.md).

6. Выполни коммит. Покажи хэш и title. Сразу после — запиши подпись в журнал (см. секцию «Подпись коммита» внизу), используя sessionId, вычисленный в шаге 5.

7. **Ревью:** правки файлов возможны только в worktree (см. `~/.claude/CLAUDE.md`), поэтому `/commit` сам всегда выполняется из worktree — `repo=` для `/review` автоматически указывает на активный worktree, как того требует «Вход» `/review` при `mode=full`. Запусти цикл `/review` на свежий HEAD (sessionId раннер определяет сам). Механика — в `agents/review-runner.md`: ревьюеры параллельно → review-judge → implementer-фиксы → fix-коммит → re-review до clean. Числового лимита раундов нет, цикл останавливается когда перестаёт давать прогресс (критерии — раздел «Когда остановиться» в `agents/review-runner.md`). При `blocked` — разбор по `/review`, раздел «Что делать с ответом».

8. **Push:** мы всегда в worktree (см. шаг 7) — НЕ push. Если всё же оказалось, что cwd — основное дерево (изменения там могут появиться в обход хука, например через Bash: `rm`, генератор, форматтер) — это аномалия: не коммить молча, сообщи пользователю и дай ему решить. Что дальше будет с worktree-веткой — merge в main или push и pull request — решает вызвавший флоу по проектному CLAUDE.md (`~/.claude/rules/workflow.md` шаг 11), и делает это сам, вне `/commit`. Дефолт «push требует явного разрешения пользователя» — см. `~/.claude/CLAUDE.md` и per-project override.

## Аргументы

`$ARGUMENTS` парсится так:
- Если начинается с тикета (PROJ-12345, TICKET-678 и т.д.) — используй как тикет + остаток как title
- Если просто текст — используй как title
- Примеры:
  - `/commit` — автоматический title
  - `/commit fix auth bug` — title: "Fix auth bug"
  - `/commit PROJ-12345` — тикет PROJ-12345, title автоматический
  - `/commit PROJ-12345 fix auth` — тикет PROJ-12345, title: "Fix auth"

## Подпись коммита (каноника; /review и /finalize ссылаются сюда)

Каждый созданный коммит привязывается к сессии — чтобы по коммиту найти сессию и вернуться в неё через claude --resume <UUID>.

1. **sessionId** — `$CLAUDE_CODE_SESSION_ID`, руками id не выводи:
   ```
   echo "${CLAUDE_CODE_SESSION_ID:-unknown}"
   ```
   Claude Code сам выставляет переменную в окружении Bash и хуков. У сабагента она равна id главной сессии, в форке — свой id; сжатие контекста id не меняет.

   **Пустая переменная — поломка харнеса, но не блокер:** в журнал, поле или trailer пиши литерал `unknown`, работу не блокируй. Главная сессия сразу говорит пользователю в ответе, что переменная пуста; сабагент сообщает через канал flow-issue (запись в журнал flow-feedback и строка `flow-issue:` в reply, см. `agent-core-preamble`).

   Никогда не подставляй вместо `unknown` id, добытый другим способом: любые «возьму самый свежий .jsonl» / `ls -t` дают id ЧУЖОЙ параллельной сессии, а не текущей (так 2026-07-24 коммиты и техдолг одной сессии уехали под id другой, которая просто активнее писала в тот момент).
2. **Журнал** (всегда, в любом репо): допиши строку в `~/.claude/projects/<slug>/memory/commit-sessions.md`:
   ```
   <short-hash>  <sessionId>  <YYYY-MM-DD>  <title коммита>
   ```
   `<slug>` считается по **main-репо** (не worktree): `PROJECT_ROOT=$(dirname "$(git rev-parse --git-common-dir)")`, затем `printf '%s' "$PROJECT_ROOT" | sed 's|[/.]|-|g'`. `mkdir -p` директории. Пишется через Bash (echo >>), не через Write — путь под `~/.claude/`.
3. **Trailer** (`Ref: <sessionId>` в message) — только при явном opt-in в проектном CLAUDE.md, см. шаг 5. Дефолт — без trailer: подпись живёт только в локальном журнале.

Найти сессию по коммиту: `grep <short-hash> ~/.claude/projects/*/memory/commit-sessions.md` → `claude --resume <UUID>`. После rebase/amend хэш меняется — новая строка пишется при новом коммите, старая остаётся как история.
