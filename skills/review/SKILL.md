# Code Review

**Обязателен после КАЖДОГО коммита, без исключений.** Даже для .md, конфигов, документации. Это исключение из общего правила «не делегировать тривиальное» — ревью работает на всё, что попало в git.

Цикл ведёт агент `review-runner`; тебе остаётся запустить его и обработать короткий итог. Механика цикла (выбор ревьюеров, раунды, критерии остановки) — в `agents/review-runner.md`.

## Вход

- **repo** — абсолютный путь к git-репо (в worktree / для `~/.claude/` — обязательно явный). При `mode=full` обязан указывать на активный worktree, не на основное дерево — ответственность за это на вызывающем флоу: запись в основное дерево запрещена хуком `worktree-boundary.sh`, и цикл упрётся в отказ посреди работы.
- **head** — ref (default `HEAD`).
- **mode** — `full` (default) | `analysis-only` (чужой код, например `/review-mr`: без правок, DEBT и коммитов).
- **plan** (опционально) — абсолютный путь к плану, если реализация шла по плану; **plan_scope** — какой шаг плана реализует коммит (`C1`, `C2`, ... или `whole`, default `whole`). Передавай всегда, когда план есть.
- **scope** — `commit` (default) | `branch` (один раз за задачу итоговый проход «свежий читатель» по всей ветке, см. `agents/review-runner.md`, «В раунде по ветке»). **base** — только при `scope=branch`, от чего считать ветку (default — merge-base с `origin/HEAD`). `scope=branch` несовместим с `plan`, `plan_scope`, `extra`: распорядитель вернёт `blocked`.
- **Контекст задачи** — 1-2 строки для ревьюеров и judge.
- **extra** (опционально) — дополнительные указания ревьюерам (например, путь к diff и «только блокеры и важное»).

## Запуск

`Agent(review-runner, prompt="repo=… head=… mode=… scope=… base=… plan=… plan_scope=… task=… extra=…")` — передай все полученные аргументы. Содержимое находок в свой контекст не бери.

## Что делать с ответом

Reply — `статус: clean | fix-needed | blocked`, причина, раунды, хэши fix-коммитов, DEBT.

- `clean` — вернуть управление вызвавшему флоу.
- `blocked` — при `mode=full` сначала разбери самостоятельно: прочитай verdict последнего раунда и причину. Если понятно, как закрыть (например, нужно решение, закрывающее обе стороны «качелей»), — дай `implementer`'у правку, закоммить и запусти цикл заново на свежем коммите (без `plan=`/`plan_scope=`: на fix-коммитах сверка с планом запрещена, см. `agents/review-runner.md`; либо перезапускай на исходном head — тогда SHA не меняется, и действует «Перезапуск на коммите, где папка уже есть»). Не больше 2 перезапусков подряд по одной и той же причине, потом к пользователю. Причину прошлого `blocked` передавай в `extra=` — распорядитель историю между запусками не помнит. Пользователю — сразу, если нужен его выбор (продуктовый, меняющий договорённость) или ты не видишь, как чинить. При `mode=analysis-only` (чужой код, правки и коммиты запрещены) самостоятельного разбора с `implementer`'ом нет: один перезапуск на том же коммите (см. «Перезапуск на коммите, где папка уже есть»), а если не помогло — причина вызвавшему флоу (для `/review-mr` это доклад пользователю).
- `blocked` при `scope=branch` — не повторяй проход по ветке вслепую. Если ошибка входа («несовместим с plan/extra», «укажи base=», «нечего ревьюить», «base не предок head») — не перезапускай с теми же аргументами, поправь аргументы. Если verdict ветки есть (`<repo>/.tmp/review/branch-<sha7>/verdict.md`): при отсутствии fix-коммитов сначала выполни FIX-группы из этого verdict'а (`implementer`, коммит), затем обычный `scope=commit` на HEAD; если fix-коммиты были — обычный `scope=commit` на HEAD (иначе находки читателя по ветке теряются). Упал до verdict — перезапусти `scope=branch`, предварительно переименовав папку `branch-<sha7>` по правилу «Перезапуск на коммите, где папка уже есть».
- **Пустой или оборванный reply** (распорядитель упал, ушёл в лимит, не вернул статус) — не к пользователю, а разобрать. Сначала убедись, что подчинённые агенты упавшего распорядителя уже не работают (иначе гонка за дерево). При `mode=full`: `git -C <repo> log` и `status`. Fix-коммиты распорядителя уже есть — перезапусти его на свежем HEAD (без `plan=`/`plan_scope=`); нет — перезапусти на том же коммите; в дереве остались незакоммиченные правки implementer'а — посмотри их, закоммить годное или откати, потом перезапуск. При `mode=analysis-only` файлы проекта не трогать: только перезапуск на том же коммите. Во всех ветках перед перезапуском действует «Перезапуск на коммите, где папка уже есть». При `scope=branch` действует правило про `blocked` при `scope=branch` выше: перезапуск не вслепую на том же коммите. Пользователю — только если повторный запуск тоже сломался и причина неясна.
- **Перезапуск на коммите, где папка уже есть.** Если `<repo>/.tmp/review/<sha7>` коммита, на котором идёт перезапуск (в том числе нового HEAD — упавший распорядитель мог его уже создать), существует — переименуй: `mv <repo>/.tmp/review/<sha7> <repo>/.tmp/review/<sha7>-stale-$(date +%s)`. Так же для папки `branch-<sha7>`: добавь к её имени `-stale-$(date +%s)`. Не `rm`: иначе файлы прошлого запуска примут за свежие. Папка в `.tmp` — не правка проекта, действует и в `analysis-only`.
- `fix-needed` (только `analysis-only`) — в причине путь `verdict: <путь>`; прочитай verdict самостоятельно, вызвавшему флоу нужно его содержимое.
- Хэши fix-коммитов — для отчёта.
- Строка «План разошёлся» (при любом статусе) — запустить `planner` в режиме доработки, см. workflow, шаг 7.
- Строка `flow-issue:` — workflow, «Контроль качества», п. 2b; с кодом замены агента (#81438 - баг Claude Code: ответ продолженного агента не доходит до распорядителя, и тот заменяет агента свежим) — штатный откат, см. п. 2c.

## Когда НЕ вызывать

- Коммита ещё нет (working tree грязное) — сначала `/commit`.
- Черновики вне git — ревью не применимо.

## Параллелизм с другими задачами

Пока цикл идёт, не стартуй другой коммит в тот же репо — он делает fix-коммиты.
