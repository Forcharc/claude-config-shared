Записать техдолг.

## Шаг 0: Определить путь хранения

Проверь наличие настройки `techdebt_location` в project CLAUDE.md (`.claude/projects/<project>/CLAUDE.md`):

- `techdebt_location: local` → базовый путь = `.claude/projects/<project>/memory/tech-debt/` (где `<project>` — директория текущего проекта, та же что для memory). Подпапка `tech-debt/` внутри `memory/` нужна, чтобы хук `worktree-boundary.sh` разрешал запись из worktree — он пропускает всё под `memory/**`. Этот режим не завязан на worktree дальше — можешь сразу перейти к «Инструкция».
- `techdebt_location: repo` или настройка отсутствует (default) → базовый путь = `<git root>/docs/tech-debt/`, где `<git root>` — корень **активного worktree**, не главного дерева репозитория. Продолжай в следующей секции.

### `repo`-режим: писать можно только в worktree

Хук `worktree-boundary.sh` блокирует любой Write/Edit в главное рабочее дерево любого git-репозитория, включая `~/.claude/`, кроме файлов, которые игнорирует git (в repo-режиме это не влияет: `docs/tech-debt` отслеживается). Раньше здесь был особый случай «репо `~/.claude/` — пиши прямо в главное дерево», он больше не действует ни в каком репозитории.

1. Вычисли `<git root>` = `git rev-parse --show-toplevel`. Если этот алгоритм переиспользует саб-агент с явным `repo=` в промте (например `review-judge`) — команда выполняется от `<repo>` (`git -C "<repo>" rev-parse --show-toplevel`), не от cwd агента.
2. Проверь, что `<git root>` — worktree, а не главное дерево: `git -C "<git root>" rev-parse --absolute-git-dir` — если результат матчит `*/.git/worktrees/*`, это worktree (тот же признак, что в `/commit` шаг 8). Иначе — главное дерево.
3. Если главное дерево:
   - **Ты, главная сессия** (есть `EnterWorktree`) — вызови `EnterWorktree`, пересчитай `<git root>` внутри неё и продолжи с пункта 1. Это тот же файл-write, что и любая другая правка — отдельного исключения для техдолга нет.
   - **Ты саб-агент без `EnterWorktree`** (`review-judge` и другие, переиспользующие этот алгоритм) — `repo=` обязан прийти уже указывающим на открытый worktree, это гарантия контракта вызывающего флоу (см. `/review`, раздел «Вход»). Если пришло главное дерево — это баг вызывающего флоу, не твой: файл не пиши, сообщи об этом в reply вместо тихой записи не туда.

Далее все пути относительно `<базовый>` = `<git root>/docs/tech-debt/`.

**Если `<базовый>/INDEX.md` или `<базовый>/TEMPLATE.md` не существует** — сначала вызови `/techdebt-init`, затем продолжи.

## Инструкция

1. Определи следующий номер `td-NNN`. Не доверяй только локальному `<базовый>/INDEX.md` — worktree мог давно отбранчеваться от `main`, там уже могут быть более свежие номера. Сверься с версией того же файла на `main` (доступна без fetch — worktree и главное дерево используют общий `.git`, объекты общие): `git -C "<git root>" show main:docs/tech-debt/INDEX.md 2>/dev/null`. Номер = максимум из локального INDEX.md и `main`:INDEX.md, плюс 1 (если версии на `main` нет — только локальный). Если записей нигде нет — начни с номера 001.

   Это снижает, но не убирает коллизии номеров при параллельной работе нескольких worktree — сама коллизия ожидаема и не дефект (см. `~/.claude/rules/workflow.md`, пункт про td-номерные коллизии); руками номера не перенумеровывай, merge и `/finalize` разберутся.

2. Создай файл `<базовый>/td-NNN-slug.md` по шаблону из `<базовый>/TEMPLATE.md`. Slug — 2-3 слова через дефис, описывающие суть.

3. Заполни все поля:
   - **id**: td-NNN
   - **title**: краткое описание
   - **module**: в каком модуле проекта
   - **tags**: тип проблемы (duplication, performance, reliability, security, design, cleanup, testing)
   - **priority**: 🔴 критично / 🟠 важно / 🟡 средне / 🟢 мелочь
   - **found**: сегодняшняя дата
   - **task**: что делал когда нашёл
   - **status**: open
   - **originSessionId**: UUID сессии, которой принадлежит долг. Если передан аргумент `parentSessionId` - используй его. Иначе возьми `$CLAUDE_CODE_SESSION_ID`:
     ```bash
     echo "${CLAUDE_CODE_SESSION_ID:-unknown}"
     ```
     Пустая переменная — см. `/commit`, секция «Подпись коммита»; `unknown` пиши как есть, id другим способом (`ls -t`, «самый свежий .jsonl») не добывай — чужой id здесь хуже отсутствующего: `/finalize` в другой сессии подхватит этот долг как свой и закроет за владельца.
     Используется `/finalize` для фильтрации долгов этой сессии.
   - **Проблема**: подробное описание — что не так и почему это плохо
   - **Где**: конкретные файлы и строки
   - **Предлагаемое решение**: как исправить (если есть идея)
   - **Риски**: что будет если не исправить

4. Добавь запись в `<базовый>/INDEX.md` в секцию соответствующего модуля (если секции нет — создай её) в формате:
   `- [td-NNN](td-NNN-slug.md) ПРИОРИТЕТ `тег` Краткое описание`

5. Допиши `td-NNN` строкой в `<git root>/.tmp/active-tds.md` (создай файл если нет). При `techdebt_location: repo` `<git root>` уже вычислен в шаге 0; при `local` вычисли так же (`git rev-parse --show-toplevel` от cwd) — этот шаг не завязан на выбранный режим хранения, только на наличие git-репозитория. `.tmp/` уже в gitignore — файл не коммитится, живёт только пока жив worktree. `/finalize` читает этот файл как «созданные в этой сессии/worktree», в дополнение к фильтрации по originSessionId.

   Если cwd не внутри git-репозитория (нет toplevel) — пропусти этот шаг, `/finalize` будет работать только через originSessionId.

6. Покажи пользователю что записал.

## Аргументы

`$ARGUMENTS` парсится так:
- Если содержит `parentSessionId=<UUID>` - используй этот UUID как originSessionId (вместо `$CLAUDE_CODE_SESSION_ID`). Это нужно когда td-запись создаёт sub-agent по алгоритму этого скилла (например review-judge): originSessionId должен указывать на сессию пользователя, переданную в его промте.
- Остальной текст - описание техдолга от пользователя. Используй как основу для записи, уточни детали из контекста текущей сессии.
